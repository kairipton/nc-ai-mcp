# VARCO Sound 작업 절차

너는 소리를 들을 수 없다. 판단은 `analyze_audio`·`compare_audio` 수치로 하고, 최종 선택은 사람 귀에 맡긴다.
처음 쓰는 세션이면 `get_guide`를 먼저 읽는다(프롬프트 작성법·파라미터 효과·출력 특성).

## 0. 시작 전 확인
1. **프로젝트 종류와 저장 위치**를 정한다.
   - 유니티(`Assets/`·`ProjectSettings/` 있음) → `Assets/Audio/SFX/` 아래(유니티가 자동 임포트). 환경음 루프는 `Assets/Audio/Ambience/`.
   - 웹게임(`package.json`·`public/` 있음) → `public/audio/` 아래.
   - 둘 다 아니면 사용자에게 묻는다. 기존 오디오 폴더가 있으면 그 규칙을 따른다.
2. **라우드니스 기준**을 찾는다. 프로젝트 문서(`docs/`, `CLAUDE.md`, 기존 사운드 명세)에 기준이 있으면 그대로 쓴다.
   없으면 **사용자에게 묻는다**(제안 예: 효과음 -18 LUFS·피크 -1dBFS). 임의로 정하지 않는다.
3. **포맷 기준**: 유니티는 wav(압축은 임포트 설정), 웹은 ogg(+필요하면 mp3). 프로젝트에 기존 규칙이 있으면 그것을 따른다.
4. `list_history(query=...)`로 **비슷한 소리를 이미 만들었는지** 확인한다. 있으면 재사용·변형을 먼저 검토한다.
5. `check_credits`로 **크레딧 모드**(`credit_mode`)와 `mode_rules`, 남은 세션 예산을 확인하고 아래 2장의 그 모드 규칙을 따른다.
   사용자가 대화에서 "아껴서", "절약 모드로"라고 하면 설정보다 더 엄격한 모드를 따른다(더 느슨하게는 안 됨).

## 1. 표준 순서
1. 요구사항을 정리한다: 용도, 길이감, 무게·밝기, 어택 성격, 공간감, 반복 재생 여부.
2. `generate_sfx`로 후보를 모드가 정한 수만큼(절약·보통 n=3, 플렉스 n=6). n 은 **3의 배수**로(호출 기본료가 대부분). `purpose`·`description`(영문 짧게)·`note`(프로젝트·용도)를 반드시 채운다.
3. 결과 파일에는 **같은 소리가 여러 번** 들어 있는 경우가 많다(실측 2~7번). `quick_metrics.event_count`가 2 이상이고
   단발이 필요하면 `split_events`로 나눈다. 이어지는 소리(환경음·연속 동작)면 `trim_silence`만.
4. `compare_audio`에 목표를 지표로 옮겨 넣고 순위를 본다(나눈 조각들끼리 비교).
   - 예) 짧고 묵직한 타격: `{"first_event_duration_s":0.3, "attack_ms":10, "spectral_centroid_hz":400, "low_ratio":0.7}`
5. 목표와 멀면 **원인 지표**를 보고 프롬프트를 고쳐 재생성한다(무게 부족 → heavy/deep/low thud 추가, 또는 `version="v2"`).
6. 반복 재생되는 소리면 변형이 2~3개 필요하다. **split_events 조각이 이미 같은 소리의 다른 테이크**이므로 먼저 그것을 쓴다.
   부족할 때만 가장 나은 1개로 `generate_from_sample`(strength 0.3~0.6) — 절약 모드에서는 쓰지 않는다.
7. 최종본: `fade`(끝 클릭 방지 20~50ms, 필요할 때) → `normalize`(프로젝트 기준) → `convert`(`output_path`를 게임 폴더로).
8. `build_audition_page`로 후보 2~4개를 묶어 사용자에게 **귀로 확인**을 요청한다. 페이지 경로를 알려 준다.
9. 사용자가 고른 파일만 게임 폴더에 남긴다. 탈락 후보는 기본 출력 폴더(후보 보관소)에 그대로 둔다.

환경음 루프: `generate_sfx` → `trim_silence` → `make_loop` → (필요하면 `mono_to_stereo`) → `normalize` → `convert`.
크리처 보이스: `generate_sfx`로 참조 소리 생성 → `creature_voice(source=대사녹음, reference=참조)`, 잡음 많으면 `enhance=true`.

## 2. 크레딧 모드

모드는 저장소 `config.toml`의 `[varco_sound] credit_mode`로 정한다(기본 normal). 서버는 세션 예산을 넘는 생성 호출을
`session_budget_exceeded`로 거부한다. **예산·모드를 올리는 것은 사용자만 결정한다** — 설정 파일을 직접 고치지 말고,
상황(쓴 크레딧, 남은 작업)을 알린 뒤 사용자에게 맡긴다.

소리 1개를 완성할 때의 규칙 (Text to Sound 호출 1회=3개 약 7.65 크레딧):

| | 절약 `saver` | 보통 `normal` | 플렉스 `flex` |
|---|---|---|---|
| 세션 예산(서버 강제) | 20 | 60 | 200 |
| 첫 생성 | 1회(n=3) | 1회(n=3) | 2회(n=6) |
| 재생성 | 최대 1회 | 최대 2회 | 최대 3회 |
| 변형 | split_events 조각만 | 조각 먼저, 부족하면 Variation 1회 | Variation 적극 사용 |
| 부가 API(loop·stereo·creature·enhance) | 사용자가 요청할 때만 | 필요하면 사용 | 필요하면 사용 |
| 소리 1개 예상 | 약 8~15 | 약 8~28 | 약 15~45 |

재생성 횟수를 다 쓰고도 목표에 못 미치면 멈추고 사용자에게 방향을 묻는다(프롬프트 방향·모드 변경 등).

## 3. 공통 크레딧 규칙
- 생성 전에 항상 `list_history`로 중복을 확인한다.
- 모드 규칙을 넘는 생성이 필요해 보이면 `estimate_cost`로 계산해 사용자에게 먼저 알린다.
- 같은 프롬프트를 그대로 반복 호출하지 않는다(시드가 없어 결과는 바뀌지만, 고칠 점을 먼저 반영한다).
- 후처리·분석은 무료(로컬)다. 적극적으로 쓴다.
- `check_credits`는 이 세션의 추정치만 준다. 잔액은 사용자가 대시보드에서 확인해야 한다.

## 4. 하지 말 것
- 음악(멜로디)을 `generate_sfx`로 만들지 않는다. 공개 API 에 음악 생성은 없다.
- `enhance_speech`를 효과음·자연음에 쓰지 않는다(소리를 깎는다).
- 원본 파일을 덮어쓰지 않는다(도구가 막지만, `overwrite=true`는 교체가 의도일 때만).
- 수치만 보고 "좋은 소리"라고 단정하지 않는다. 사람 확인 전에는 "후보"라고 말한다.
